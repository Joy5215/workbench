# 我的工作台

一个单文件、零依赖、离线可用的个人待办工作台。双击 `dist/我的工作台.html` 就能用，断网不影响，数据存在本机浏览器里，靠一个 `workbench-sync.json` 在多台设备之间同步。

## 产物在哪

```
dist/我的工作台.html      ← 只有这一个文件是给用户用的
```

要放进网盘同步空间、要发给别人、要双击打开的，都是它。**`src/` 里的东西不能直接用**，它们是碎片，必须经过 build 拼起来。

### 加一个视图要改哪几处

1. `config.js` 的 `VIEWS` 里加一行（k / label / ic），图标加到 `IC`
2. 新建 `views/<k>.js`，写 `VIEW_FN.<k> = function(){...}`
3. `build.py` 的 `VIEWS_FILES` 里加 `"views/<k>.js"`

`render.js` 不用改——它按 `VIEW_FN` 找函数，找不到就落到 `soon.js`。
也就是说第 1、3 步做完、第 2 步还没做时，界面是好的，只是显示「这一版先不做」。

分层原则：`core.js` 里任何一个函数都不允许出现 `document`、`localStorage`、`window`。这是能被单测的前提。

## 四象限的界面（照滴答清单）

```
┌───────────────────────────────────────┐
│ 收集箱                          2     │  ← 有条目才出现
├───────────────────┬───────────────────┤
│ ● 重要且紧急   2  │ ● 重要不紧急   2  │     2×2 撑满屏，整页不滚，
│   □ 交周报        │   □ 整理 Q4 复盘  │     每格自己滚
│     今天          │     11月20日      │
├───────────────────┼───────────────────┤
│ ● 不重要但紧急 1  │ ● 不重要不紧急 1  │
│   □ 订会议室      │   □ 刷短视频      │
│                       ( + ) ← 悬浮按钮 │
└───────────────────┴───────────────────┘
```

- **录入**：点右下角 `+` → 底部浮层问「放到哪一格」→ 选完该格底部出现输入框，回车即加
- **收集箱**：顶部一条，点开底部浮层，每条四个彩点（归到某格）加一个叉（删）
- **批量粘贴**：任何输入框粘进多行，一行一条，自动吃掉 `- ` `[ ] ` `1. ` 这类前缀；
  单行照常粘贴（不拦）
- **色点**：`config.js` 里 `QUADS[i].c`，只用于这一点，不铺背景
- 今日页仍是完整列表，每行悬停露出「急 / 重」切换

## 四象限怎么存的

`todos` 里每条记录有两个布尔字段：`urg`（紧急）、`imp`（重要）。**不存「哪个格子」**。

理由：一条任务「重要」这件事本身有含义，落在哪个格子是它的推论。存两个布尔，以后加筛选、加排序、做自动化都能直接用；存格子名等于把推论当真相，改判就要迁移数据。

| 任务状态 | 格子 |
|---|---|
| urg=1, imp=1 | 重要且紧急 |
| urg=0, imp=1 | 重要不紧急 |
| urg=1, imp=0 | 不重要但紧急 |
| urg=0, imp=0 | 不重要不紧急（未标记的任务都在这里） |

未标记的任务全落在第四格——那格的语义就是「还没想清楚该不该做」，正好是收件箱倒过来的待办。不需要再造一个「未分类」格子。

## 构建

```bash
python3 build.py            # → dist/我的工作台.html
python3 build.py --check    # 只校验 dist 是否与 src 一致，不改文件
```

为什么是「拼接」而不是 webpack/vite：产物必须能双击打开、能塞进网盘同步空间、断网可用。任何引入 `node_modules` 的方案都会破坏这三条。拼接器 60 行，够用。

## 测试

```bash
bash tests/run.sh
```

五项，任一失败非 0 退出：

1. **构建一致性** —— `dist` 是否等于 `src` 拼出来的（防止改了源码忘了重建）
2. **单元测试** —— 22 个用例，全部对着一次真实翻车写的（见下）
3. **行为等价** —— 起本地服务，用 chromium 打开基线和构建版，各加 3 条、删 1 条、切视图，比对脱敏后的 localStorage、渲染文本、DOM 行数、控制台错误
4. **四象限交互** —— 31 条：满屏布局、选格录入、勾掉消失、收集箱归位、多行粘贴拆条
5. **GitHub 通道与收件** —— 18 条：`?add=` 三种归宿、前缀清理、query 擦除、仓库地址容错、token 不进数据文件

## 两条同步通道

| | GitHub | 文件夹 |
|---|---|---|
| 手机能用 | ✅ | ❌ 浏览器不给网页选文件夹 |
| 需要什么 | 一个 token | 电脑 + 网盘客户端 |
| 数据在哪 | 仓库里一个 json | 网盘同步目录 |
| 适用 | 日常主力 | 不想给仓库权限时 |

GitHub 这条能成立，是因为它家开了 CORS：

```
OPTIONS https://api.github.com/repos/o/r/contents/x
access-control-allow-origin: *
access-control-allow-methods: GET, POST, PATCH, PUT, DELETE
access-control-allow-headers: Authorization, Content-Type, If-Match, ...
```

百度网盘、坚果云、飞书的响应里都没有 `allow-origin`，所以那三家只能绕。

**冲突**：PUT 带 `sha` 当乐观锁。撞车了（409/422）就重拉、合并、再推一次——不重试的话那一次冲突等于「我这台的改动丢了」。

**token 只存本机**，`myworkbench.gh` 这个 key，不进 `workbench-sync.json`。用 fine-grained token，只授权一个仓库的 Contents 读写。

## 笔记：视频、思维导图、Markdown

三种能力都不是飞书或 WPS 的专利，网页里都能做：

| 想要 | 怎么做 | 实测 |
|---|---|---|
| 嵌视频 | B 站 `player.bilibili.com`、YouTube `/embed/` 走 iframe | B 站页面**没有** `x-frame-options`，能嵌；YouTube 在这台机器上超时，未验证 |
| 思维导图 | ```mermaid 代码块 → `mermaid.ink/img/<base64>` 出的 PNG | 返回 `image/png` 200，中文正常 |
| 读 Markdown | 内嵌 marked(35KB) + DOMPurify(21KB) | 标题/列表/表格/代码块都过 |

**为什么飞书和 WPS 只给一张卡片**：`docs.feishu.cn` 返回 `x-frame-options: DENY`，飞书官方 FAQ 还自认 iframe 内 cookie 不可用、扫码都登不上。WPS 同理由（靠登录态）。这两家点开去那边看，不硬塞。

**为什么不留 mermaid.js 在本地**：3.5MB，为了画几张图不值得。换成 GET 图床，代价是断网看不到图——所以图下面一直保留源码，图挂了也读得到。`onerror` 会把图换成源码。

**正文为什么要净化**：笔记会进同步文件，那个文件另一台设备、共享仓库、手改都能写进来。不净化等于给 XSS 开个口。`tests/gh.test.cjs` 里专门写了一条带 `<script>` 和 `onerror` 的笔记，断言它进不了 DOM。

## 从外面收件

```
?add=文本            进收集箱
?add=文本&to=do      直接进「重要且紧急」（plan / deleg / drop 同理）
```

## 这次拆分修掉的一个真 bug

单测里有一条一开始是红的，查出来是**数据会凭空消失**：

```
设备 A 删掉某条       → up=50, del=1
设备 B 在收到之前编辑了它 → up=80, 没有 del 字段
B 先同步上来
```

旧代码走「远端 up 更大 → 覆盖本地」，但它只覆盖远端**有的**键。远端没有 `del`，本地那个 `del=1` 就留在原地——记录内容更新了，却永久藏在墓碑里，列表上永远看不见。

修法在 `core.js`：远端更晚且没带 `del`，就把本地 `del` 清成 0。`tests/core.test.cjs` 里「远端更大但不是墓碑」那条用例守着它。

因为修了这条，构建版与 `baseline.html` 在这个场景下**不再等价**——这是有意的，不是回归。

## 已知限制

| 限制 | 后果 | 能不能修 |
|---|---|---|
| 数据在 `localStorage`，key `myworkbench.v1` | 清浏览器数据就没了；`file://` 下所有本地 HTML 共享同一 origin | 不修。真身在 `workbench-sync.json`，重连就能补回来 |
| 墓碑保留 30 天 | 超过 30 天没开机的设备，删掉的东西会复活 | 不修，30 天够用 |
| 冲突按每条记录的 `up` 判 | 两台设备时钟差太多会判错 | 只提示不自动覆盖，「立即同步」一次算完 |
| 时钟回拨 | `bumpUp` 取 `max(now, old+1)`，能兜住小幅回拨 | 已兜 |
| 中文路径 | 网盘同步空间里放中文目录名没问题，但 `file://` 下路径含 `#`/`?` 会打不开 | 别用这两个字符 |
